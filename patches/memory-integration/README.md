# Memory Integration Patch

**Status:** standalone Java 21 patch / offline tool. Not automatically loaded by Fabric.

## Purpose

Integrate the 24 Nao characters' **separate episodic Markdown journals** into one
attributed, shared memory index without replacing their memories or overriding
the player's **single authoritative personality**.

Input: `config/doppelganger/memories/nao_personality.md` and
`nao_01.md` through `nao_24.md`.

Output: `config/doppelganger/memories/nao_integrated_memory.md`.

### Guarantees

- All 24 input journals are required; missing files abort before output.
- The original 25 Markdown files are never modified.
- Each integrated event includes `nao=01` through `nao=24`, so source identity remains visible.
- Chronological order: game day, tick, then Nao number.
- Duplicate identical entries **within one Nao file** are removed; identical experiences from different Nao are retained.
- Unsupported or malformed event lines are counted and rejected.
- Shared preferences are copied as a snapshot, **not learned or averaged** from individual memories.
- Output is rewritten from the sources on each run, avoiding repeated appends.
- Output uses a temporary file and atomic replacement when supported.

## Run

Java 21 JDK is required; the patch uses only the Java standard library.

From repository root:

```bash
javac -d patches/memory-integration/out patches/memory-integration/src/org/nagineco/patch/memoryintegration/MemoryIntegrationPatch.java
java -cp patches/memory-integration/out org.nagineco.patch.memoryintegration.MemoryIntegrationPatch config/doppelganger/memories
```

If your server stores its files elsewhere, pass that server's actual memory directory.

## Example

```text
config/doppelganger/memories/
├── nao_personality.md
├── nao_01.md
├── ...
├── nao_24.md
└── nao_integrated_memory.md  # generated by patch
```

A generated event looks like:

```md
- nao=01 day=1 tick=20 position=(5.0,64.0,7.0) action=EAST emotion=CURIOUS reason=EXPLORE
```

## Shared personality vs. shared memory

`nao_personality.md` expresses **player-authored values and preferences**. It is the
single authoritative personality for all 24 Nao.

`nao_XX.md` expresses the **individual history** of Nao XX.

`nao_integrated_memory.md` is a **shared, attributed view** of all 24 histories.

The integrated memory is **not yet read by the live NPC decision code**. Existing
Fabric NPCs currently use in-memory imitation models that combine demonstrations
with shared preference weights. A subsequent integration can consume the generated
index as a durable cross-character knowledge source, but must avoid double-counting
samples already loaded from the individual journals.

This patch is deterministic data integration, not semantic understanding of
free-form diary text, true emotion recognition, personality cloning, or an LLM.

## Operational notes

- Stop the Minecraft server or ensure all journals have been flushed before running
  the patch. Concurrent writes are not coordinated.
- Back up the memory directory before first use.
- Journal contents may reveal in-game locations and user-supplied emotion labels;
  keep server data private.
- Build and end-to-end Minecraft integration are not verified yet.


## Fabric automatic integration (default ON)

The main Fabric mod now compiles this patch source through Gradle and invokes
`MemoryIntegrationPatch.integrate(Path)` automatically when the memory store
is initialized and after journals are flushed by `/doppel next` or
`/doppel stop`. The standalone Java CLI remains available.

Operator commands: `/doppel mip status`, `/doppel mip logs`,
`/doppel mip run`, `/doppel mip on`, `/doppel mip off`.

The default is **ON**. The setting persists at
`config/doppelganger/mip.enabled`. Turning MIP OFF stops automatic integration
but never deletes journals or the last generated integrated index. Turning ON
re-integrates immediately when memory storage is available. Console logging is
enabled by default; the last 20 integration messages are available via
`/doppel mip logs`. Integration occurs at the documented command boundaries,
not continuously on every Minecraft tick.

The live NPC AI still does not consume the integrated Markdown index.


## Daily Minecraft-time schedule

MIP now automatically integrates **once per in-game day at 00:00 (midnight)** by
default, provided the Doppel system has been started and MIP is ON. In Minecraft
Java, midnight is **tick 18000**; tick 0 is **06:00**, not midnight.

Set a different time (24-hour Minecraft clock):

```mcfunction
/doppel mip time
/doppel mip time 00:00
/doppel mip time 12:30
/doppel mip status
/doppel mip logs
```

The schedule is saved in `config/doppelganger/mip.time` and survives restarts.
Automatic integration flushes pending individual memory samples first and logs
the outcome to the server console and `/doppel mip logs`.

**Scheduling semantics:** it triggers on normal forward crossings of the
configured clock time; it does not replay missed triggers after large time
jumps. It runs at most once per underlying Minecraft day number. Rewinding the
clock for the 24 training loops does not trigger the same day again. With the
existing prototype's repeated clock resets, this means the daily merge may
happen once across multiple training loops, not once for each loop. Use
`/doppel mip run` for an immediate merge. Turning MIP OFF suppresses
scheduled merges without deleting memories. `/doppel next` and
`/doppel stop` now flush journals but do not themselves schedule a merge.
